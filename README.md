# 觅重 MiZhong 0.5.3

本地文件查重工具。macOS 为 SwiftUI 原生应用，0.5.0 新增电子书内容预览与正文相似查找。Windows 开发与验证已暂停，现有版本保留为 0.3.0 已交叉编译、待实机验收的原型。

## 0.5.0 新增：电子书内容查重

- 独立“内容预览”板块，按实际正文比较文字版 PDF、EPUB、MOBI、AZW3。
- 支持跨格式、改名、重排版、修订版与节选内容的相似查找。
- 展示双向正文覆盖率、匹配分类和重合片段，并提供正文预览。
- EPUB 按书脊阅读顺序解析；MOBI/AZW3 支持未加密的未压缩和 PalmDOC 压缩正文。
- 扫描版 PDF、加密/DRM 文件及暂不支持的 HUFF/CDIC 压缩会明确标记。
- 正文缓存只写入本机 Application Support；NAS 始终只读，不保存任何账号或密码。

## 直接运行

- macOS：打开 `dist/觅重.app`，或使用 `dist/MiZhong-0.5.3-macOS.dmg`。支持 macOS 14+，同时包含 Apple Silicon 和 Intel 架构。使用本机临时签名，尚未正式公证。

## 0.5.3 电子书大库预筛

超过 200 本电子书时默认先按归一化文件名和近似书名建立候选，再比较正文指纹；小库仍完整比较。侧栏可关闭该预筛，以覆盖“文件名完全改掉”的同书，但速度会下降。

## 0.5.2 大库性能优化

- 大任务检查点改为紧凑二进制格式，同时兼容读取旧版 JSON 任务。
- 10 万文件下自适应降低检查点写入频率，减少重复序列化和磁盘占用。
- 去除扫描阶段的全量路径排序、唯一文件硬链接别名数组和无用完整哈希分组。
- 电子书正文指纹改用滚动哈希与 winnowing，章节移动或节选仍能匹配，并避免随全文长度增长的大型字符数组。
- 电子书提取采用本地 4 路、NAS 2 路并发，结果顺序保持确定。
- Windows 0.3.0 原型：解压 `dist/MiZhong-0.3.0-Windows-x64.zip`，运行文件夹内的 `MiZhong.exe`。需要 **.NET Desktop Runtime 10 x64**（不是仅 ASP.NET Runtime）。下载：https://dotnet.microsoft.com/download/dotnet/10.0 。本轮没有增加 Windows 功能或完成 Windows 运行验收。
- Windows 的 HEIC/WebP 解码取决于系统已安装的 WIC 图片解码器；缺少解码器会记入错误列表。

## 0.4.0 使用方式

### A/B 资料库对比

1. 在侧栏切换到「A/B 对比」。
2. 添加 A「已整理资料库」和 B「待整理目录」，两侧均可添加多个目录。A 与 B 必须分开，不能相同或互相包含。
3. 设置大小、扩展名和子目录范围，开始新扫描。
4. 「完全重复」只显示连接 A 与 B 的重复组，A 始终受保护；「B 中独有」显示本次范围内未在 A 找到相同内容的 B 文件。

“B 中独有”不表示该文件在 B 内只出现一次，B 内部仍可能重复。结论受大小、类型、隐藏文件、排除目录和递归设置限制；扫描不完整时不展示确定的独有结论。继续历史任务使用原任务参数，重新修改侧栏后应「开始新扫描」。

### 重复文件夹

勾选「识别重复文件夹」后，在结果中的同名标签页查看。比较依据为相对文件路径、大小、完整 SHA-256 和目录结构（包括已遍历的空目录）。至少包含一个符合条件文件的文件夹才会成为结果。

比较范围仍由本次筛选条件决定，被排除的内容不参与；因此结果不等于整个磁盘目录的所有内容都完全相同。未完整遍历或读取失败的目录不会作为已确认的重复文件夹。此标签页仅供审核和 Finder 定位，不提供整夹删除。

A/B 对比及重复文件夹识别需要为更多符合条件的文件计算完整哈希，首次扫描可能比普通查重读取更多数据。

### 保存、恢复与 NAS 重试

- 扫描任务自动保存在本机的 `~/Library/Application Support/MiZhong/Sessions/`，与可关闭的增量指纹缓存独立。
- 扫描执行到检查点时约每 3 秒保存一次，阶段切换、取消返回和结束时立即保存；开始处理前先保存已知任务队列。系统读取阻塞期间不能保证每 3 秒刷新记录。
- 从「历史任务」可恢复已有结果并离线查看。历史结果处于只读状态，需「核验并继续审核」后才能选择本地文件清理。
- 继续任务时先核验目录和文件的元数据变化，失效内容重新处理，再继续未完成或失败的目录与文件；恢复后的审核选择只保留仍然有效且可操作的项目。
- 保存失败会明确显示，缺少任务文件时无法继续；若存在此前检查点，可从该记录恢复。
- 断线后先在 Finder 中重新挂载同一共享路径，再点击「继续原任务」。恢复以文件为单位，中断的大文件需要从头读取该文件，不提供文件内部字节位置续传。

## 已实现的通用功能

- 多目录、递归子目录、最小/最大大小过滤（MiB）、文件扩展名过滤、隐藏文件和排除目录。
- macOS 目录条目右键可单独关闭该根目录的递归；保存最近目录和扫描设置。
- 普通查重按大小 → 分段指纹 → 完整 SHA-256 分组。小文件直接计算完整指纹，避免再次读取。
- 文件身份去重，跳过符号链接；重叠扫描路径和硬链接不会计为独立副本。
- 暂停/继续/取消；取消返回已完成的部分结果。UI 等待当前系统读取结束后解除扫描状态。
- 本地/NAS 分开控制并发，读取失败有限重试，错误列表，默认 NAS 并发 2。
- 本地增量指纹缓存，可关闭、可清空；Mac 缓存上限 50,000 条。Mac 缓存校验设备、inode、大小、纳秒修改时间与变更时间。缓存仅用于扫描，清理不信任缓存。
- 可选相似图片（每次启动默认关闭），严格/标准/宽松阈值，重压缩、缩放、轻微居中裁剪候选匹配。
- 图片按组代表图匹配，避免传递性分组；低信息图片加入亮度检查。感知指纹分数不是识别准确率，需人工对比。
- macOS 图片缩略图缓存上限 24 MiB / 120 张，原图 Quick Look 与 Finder 定位，并排对比。
- 结果路径搜索、批量建议保留、保护目录。macOS 可指定优先保留目录。
- CSV 完全重复报告；JSON 包含完整重复结果、相似图片、重复文件夹、B 独有文件、错误与任务状态。
- 本地清理前确认明细，重新计算保留文件完整哈希并逐字节比较，每组至少留一份。后台操作，逐文件报告，保存本地清理日志。
- **网络卷清理禁止**。应用不会尝试 NAS 永久删除或模拟服务器废纸篓。
- 适配 macOS 深色/浅色外观、品牌图标、统计卡片、设置表单和图片对比页。

## NAS 与隐私

先用 Finder / Windows 文件资源管理器连接 NAS。Mac 选择 `/Volumes/共享名`，Windows 选择 `\\\\服务器\\共享` 或已映射盘符。应用没有登录表单、凭据存储、遥测或上传文件内容的代码。系统可能自行管理它已有的挂载凭据，这不由本应用控制。

Mac 在 `~/Library/Application Support/MiZhong` 保存设置、路径、文件属性、指纹、任务检查点、扫描结果及操作日志。每个任务的审核选择和扫描时保护目录保存在同目录的 `.review.json` 附属记录中。应用数据目录自动从扫描范围排除。Windows 0.3.0 的本地数据目录为 `%LOCALAPPDATA%\\MiZhong`。这些记录均不包含账号或密码。

macOS 挂载层正在阻塞的 SMB 系统调用无法强行中断；暂停/取消会在该次读取返回后的检查点生效。断线后有限重试仍失败的目录或文件会保留为待重试项目，可重新挂载后继续原任务。应用不会管理 NAS 登录或自动保存凭据。

## 验证与限制

自动化测试覆盖查重、A/B、文件夹和任务恢复等行为。真实回收站、NAS、签名、公证和 Windows 原生环境需要在对应环境中单独验证。

相似图片为启发式候选，不保证任意裁剪、旋转或语义相似的召回率；不提供相似图片自动清理。Windows 与 macOS 使用各自原生界面，Quick Look 为 macOS 专属。
